## Why this file exists

The project accumulated three planning docs written at different times. The original `brand_content_studio_spec.md` predates the reconsidered `aws_infrastructure_plan.md`, so the two contradicted each other on the vector store, backend hosting, and database. This file resolves every conflict once, and the other docs were edited to point here.

The product itself is unchanged: a **RAG**-powered studio that ingests a brand's assets, retrieves the semantically relevant pieces at generation time, and has Claude produce on-brand LinkedIn **text posts** and **designed image cards**. RAG is the differentiator and the whole point of this portfolio piece.

| 25 | Robustness — pagination + isolation (Phase 6 PR-A) | History + Assets lists are paginated with **limit+offset "Load more"**, not cursor/numbered pages — simplest correct fit at this scale. List endpoints return an envelope **`{items, next_offset}`** (`next_offset: null` when exhausted), computed with a **`limit + 1` sentinel** (no `count()` on the hot path); `limit` is `Query`-bounded to `[1,100]` (defaults 24 generations / 30 assets). Clients move to react-query **`useInfiniteQuery`** + a "Load more" button. The dashboard "generations" stat (a *total*, not a page) is backed by a dedicated **`GET /generations/count`** (declared before `/{id}` so it isn't captured by the id param). | 26 | Robustness — ingestion safety + concurrency + demo-guard (Phase 6 PR-B) | Ingestion is **bounded**: parsing runs off the event loop (`asyncio.to_thread`) under a **`PARSE_TIMEOUT_S = 30`s** `wait_for`, and the chunk count is **capped at `MAX_CHUNKS = 400` → the asset goes to `error` (not truncation)**, with nothing upserted. A demo-blocked **`POST /assets/{id}/reingest`** + an asset-row **Retry** drops any prior vectors *first* (so a re-parse can't orphan old chunks), then `mark_processing` resets the asset (clearing the error and, if it was `ready`, decrementing the workspace's ready-chunk count). Generation streams **abort + reset on workspace switch** (a per-hook `useEffect([workspaceId])` aborts the in-flight `AbortController` and re-inits state, across all four hooks), gain a **`STREAM_INACTIVITY_MS = 30000`** inactivity timeout (each `read()` races a timer; a stall cancels the reader + surfaces an error), and a **type-guarded SSE `onError`** (a non-string `error` frame falls back to "Generation failed."). The **demo-guard is reconciled** — `require_not_demo` now also guards the card-image upload (`POST …/images/upload`), matching the UI which already disabled it. The Dashboard gains an **error state** when the workspace query fails. ("Disable Generate while streaming" already shipped in Phase 1.) Completes Phase 6. | the unbounded/blocking parse + missing chunk cap (a DoS surface for untrusted files), streams that kept writing after a workspace switch or a stalled connection, and a server/UI demo-guard mismatch on image upload (PLAN Phase 6 B-series) | A portfolio app still shouldn't hang or OOM on a hostile/oversized upload; off-loading + bounding the parse is the cheap fix (no task queue). Aborting on switch keeps one workspace's stream from corrupting another's view; the inactivity timeout bounds a silently dead connection. Dropping vectors before a re-parse keeps retrieval consistent. The image-upload guard closes a real (if low-stakes) demo write path. |
| 27 | Zero-workspace onboarding gate | A signed-in owner with **no workspaces** is routed to `/setup` rather than dead-end action pages. A `RequireWorkspace` gate (mirrors `RequireAuth`) wraps the five workspace-dependent routes (`generate`/`history`/`assets`/`templates`/`settings`) and `<Navigate to="/setup">` when `useActiveWorkspace().hasNone`; the **Dashboard** and `/setup` stay ungated (soft landing + no redirect loop). The Dashboard shows a first-run "Create your first workspace" CTA; the Assets upload submit is disabled when `workspaceId` is null. **Client-only** — every workspace-scoped route already 404s without an owned workspace via `get_workspace_or_404`, so this closes a UX gap, not a security one. The gap only surfaced once real (non-demo) owner accounts existed: the demo user always owns the seeded Verdure workspace. | a fresh owner account starts with zero workspaces and the existing UI rendered null-keyed dead-ends (Generate no-op, upload → `/workspaces/null/...` 404); `hasNone` was computed but never consumed | The server already enforces the invariant, so the fix belongs in routing/UX; reusing the existing `hasNone` signal + the `RequireAuth` pattern keeps it minimal and consistent. |
| 24 | On-brand templates (Phase 5) | Upload your own branded **`.docx`/`.pptx`** with `{{placeholders}}` and pour content in — the **template's styling is authoritative** (we swap text only, **no `brand_profile` injection**, unlike the Phase 2 from-scratch docs). **Dynamic discover-then-fill:** parse each template's own tags on upload (docx via docxtpl's Jinja analysis, pptx by scanning joined paragraph text); fill the values **manually** (the user's own text — the primary path, since the win is consistent styling not verbiage) or via **one optional AI tool-use draft** whose strict schema is built from those exact placeholder names (editable before export). Render: docx via **docxtpl**, pptx via **paragraph-level run replacement** (a tag can fragment across runs; substitute on joined text, keep the first run's formatting — the one fidelity caveat vs docx). Own **`templates` collection** + **Templates nav page**; templates are **not Assets** (never ingested — they're output scaffolds, not retrieval corpus). Renders are **ephemeral** (returned as a download, not persisted). Mutations demo-blocked; AI-fill demo-allowed (generative). **Card presets split to PR-B**; style-extraction fallback for untagged templates deferred. | PLAN R4; resolves the faithful-template path of DECISIONS #21's promise | Filling the user's real file (vs rendering our own model) is the only way "on-brand" means *their* brand; dynamic discovery handles arbitrary templates; keeping the template's styles untouched is the whole value; separating from Assets avoids polluting retrieval with template boilerplate. |
| 21 | Document output (Phase 2) | One shared, typed **`DocumentModel`** (title/eyebrow/lede/sections/footer) is rendered **independently** to each format — `.docx` via **python-docx**, PDF via **ReportLab**, `.pptx` via **python-pptx** — so "matching" means *same content + brand styling from one source of truth*, **not** a docx→PDF conversion. **No LibreOffice/soffice or WeasyPrint** (heavy native deps, and a converter shell-out is an injection/SSRF surface). Two archetypes: **one-pager** (→ `.docx` + PDF) and **short-deck** (→ `.pptx`). Generations get `type:"document"` (no new collection); files persist via `StorageBackend` and download through an **auth-gated, ownership-scoped route** with the key rebuilt server-side. Flow mirrors cards: **stream prose → forced strict tool-use → build files (before persisting) → keys in terminal `{meta}`**; same hybrid retrieval + `<brand_context>` defense. PDF embeds the real brand TTF when bundled (`brand_fonts_dir`, OFL), **no runtime font fetch**; `.docx`/`.pptx` name the font. Client: a third Generate mode with archetype-shaped previews (`DocumentPage` paper / `DeckPreview` slides) + a multi-format download row (no model call). | resolves the six Phase 2 open questions in [`phase-2-plan.md`](./phase-2-plan.md) | Reuses the existing retrieval/injection-defense/storage/history seams; pure-Python keeps the image clean for ECS and removes the converter shell-out surface; one model guarantees format parity. |
| 20 | Customization (Phase 1.5) | All post-generation customization is **client-side, no `/generate`**: layout swap, per-card accent, inline copy edits, and image swap are a local **draft** rendered live, persisted on an explicit **Save** via `PATCH /generations/{id}` (only changed keys). Inline editing is **on the card** (contentEditable fields through the *same* `buildCardElement`, never Satori), edits **ephemeral until Save**; layout swaps render immediately with **deterministic text auto-fit** (no overflow warnings). The **per-card accent** is a palette color stored on `output.accent_hex` (server-validated against the workspace palette) — distinct from the **workspace UI tint** (the optional `--accent` override), which is a **Settings toggle, default on**, cosmetic only and never bleeds into semantic tokens. Re-opened History cards are **hydrated** into the same Generate editor, so customization (incl. image swap) works there too. | resolves the two open questions below | Keeps the model call for *writing*, not *designing*; one shared element preserves preview == export; a single Save/PATCH path matches the existing image-attach contract; auto-fit avoids per-layout copy constraints. |
