## Why this file exists

The project accumulated three planning docs written at different times. The original `brand_content_studio_spec.md` predates the reconsidered `aws_infrastructure_plan.md`, so the two contradicted each other on the vector store, backend hosting, and database. This file resolves every conflict once, and the other docs were edited to point here.

The product itself is unchanged: a **RAG**-powered studio that ingests a brand's assets, retrieves the semantically relevant pieces at generation time, and has Claude produce on-brand LinkedIn **text posts** and **designed image cards**. RAG is the differentiator and the whole point of this portfolio piece.

| 35 | Demo quota: one AI-call counter (known-gaps step 1) | The shared demo account's daily cap (`demo_daily_generation_limit`, 50) counts **AI actions, not saved generations**. Every paid model route (the four `/generate` streams, brand extract, template AI fill, fill from a document) depends on `enforce_demo_ai_quota`, which consumes one unit of a per-account, per-UTC-day counter in a new `usage` collection (`_id: "<user_id>:<day>"`, TTL on `expires_at`). Admission is one conditional upsert (`count < limit`, `$inc`); a duplicate key means the day's document already exists, and a plain conditional update then decides, so concurrent requests can't overshoot and a first-of-the-day race isn't refused. A unit is charged on admission (FastAPI runs dependencies before it validates the body), before the model call, and isn't refunded if the request then fails or returns without a model call (a 422, the empty-corpus 409, a template with no fields): it can over-count but never under-count, which is what bounds spend, and it's one place instead of seven handlers. Anyone could already exhaust the shared cap with valid requests, so this opens no new way to do it. Non-demo users are never counted. The setting keeps its name to avoid env churn. | The SEC-02/B2b quota (count of the demo account's `generations` today), which didn't meter the three routes that save nothing; per-IP rate limits only bounded them per visitor | The quota exists to bound aggregate demo spend, and the non-saving routes are paid calls too. | 36 | Content-Security-Policy (known-gaps step 2) | `SecurityHeadersMiddleware` sends an **enforcing** CSP on every response: `default-src 'self'`; `script-src 'self' 'wasm-unsafe-eval'` (WebAssembly for resvg PNG export and satori layout; no eval, no inline script); `style-src 'self' 'unsafe-inline'` (Radix dialogs inject a `<style>` element for scroll locking; React style props go through the CSSOM and don't need it); `img-src 'self' data: blob:` plus `images.unsplash.com` and `plus.unsplash.com`; `font-src 'self' data:` plus `cdn.jsdelivr.net` (card fonts); `connect-src 'self'` plus jsDelivr and the two Unsplash CDNs (font bytes for satori, photos fetched into data URLs); `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`. It goes on every response, not only the SPA's HTML, so a user-uploaded file opened directly can't run script either; the one exemption is FastAPI's own `/docs` and `/redoc` pages, which load Swagger UI and ReDoc from jsDelivr with an inline bootstrap. `csp_mode` (`enforce` default, `report-only`, `off`) can ease it off after a deploy with an env change and a restart, no code change. Known limits: browsers without `'wasm-unsafe-eval'` (roughly Safari < 16, Firefox < 102, Chrome < 97) can't run the card export, since allowing them would take `'unsafe-eval'`; there's no `report-uri`/`report-to` collector yet (a deploy-phase item); and when uploads move to S3 or CloudFront, that origin must join `img-src` and `connect-src`. The Vite dev server sends no CSP, so the policy is only exercised on the production build, which was walked flow by flow in Playwright with every `securitypolicyviolation` event collected. | No CSP (AUDIT SEC-11 note; QA H3) | Enforce rather than report-only first: nothing collects reports, so report-only would mostly defer the work, and a full browser pass can stand in for it. A style nonce (dropping `'unsafe-inline'`) would mean templating `index.html` per request and calling Radix's `setNonce`; the script side, which blocks XSS execution and exfiltration, is already strict, so it's declined for now. |
