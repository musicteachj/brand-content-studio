## [Unreleased]

### Security: zod 4, satori 0.33.5, and a patched fflate clear new client advisories

Two advisories published against libraries the client ships turned CI's `audit` job red on every branch:
zod before 4.6.6 can exhaust memory validating oversized constrained collections (GHSA-mrhx-c7xc-m3w5, high),
and satori before 0.33.5 can produce improperly escaped SVG (GHSA-wx4j-mvgx-mqwp, moderate). The client now
uses `zod` ^4.6.7 with `@hookform/resolvers` ^5.9.2 (the version that supports zod 4) and `satori` ^0.33.5, the
smallest jump that carries the fix. Every satori release pins `fflate` 0.7.3, which has its own advisory
(GHSA-px8p-9vwx-vf98, moderate, fixed in 0.7.5), so `client/package.json` now overrides satori's `fflate` to
^0.7.5. zod is used only by the brand identity form's schema; its one deprecated call (`z.ZodIssueCode.custom`)
is now `code: "custom"`. Two new tests run the schema through `zodResolver`, the way the form uses it, and check
that a valid form passes with trimmed color names and that each error lands on its own field; they pass on
both the old and new versions, so the form behaves the same. Cards were rendered through the production path
(`renderCardSvg` and resvg) before and after the upgrade for all three layouts, with and without a photo and
with an accent override: layout, line breaks, colors, and glyph fallbacks are unchanged, and the only
differences are anti-aliasing (about 2% of pixels); the `fflate` override changes no pixels. The lazily loaded
card renderer grows by about 31 KB and the main bundle by about 23 KB. Gate: tsc, eslint, prettier, build, and
vitest 186 (+2); `npm audit` is clean for the shipped bundle, the client dev tooling, and the root scripts.

### Changed: desktop-first, with a sidebar that collapses on narrow screens

The app is now explicitly desktop-first (DECISIONS #39): the supported minimum width is 1024 px, and there is no phone layout. Until now the sidebar was a fixed 256 px at every width, so a 390 px window left about 130 px for the page. Below Tailwind's `lg` (64rem, 1024 px at the default font size), the sidebar now starts collapsed (icon-only, 68 px) and follows the window across the breakpoint; its toggle still works at any width. Collapsed, the sidebar now keeps Sign out (an icon under your initials, which show your name on hover); it used to hide it. Below `sm` (640 px), the top bar's "New generation" button shows only its icon (it was cut off at the window's edge), keeping its accessible name, and a long workspace name in the top bar truncates instead of pushing the buttons off screen. `DESIGN.md` notes the collapse. jsdom has no `matchMedia`, so the test setup now provides one that reports a wide window (tests that render the whole app need it); `SideNav.test.tsx` stubs its own. Gate: vitest 184 (+4: expanded when wide, collapsed and still expandable when narrow, Sign out when collapsed, and following a resize both ways). Verified in the browser at 390, 820, and 1280 px on the Dashboard, Generate, and Settings: the sidebar is 68, 68, and 256 px, nothing scrolls sideways, and the top bar fits, also with a 52-character workspace name; resizing a window from 1280 to 900 px and back collapses and re-expands it.

### Fixed: removing a brand image no longer breaks the cards that use it

A card picked from the brand images points at that image's own stored file (the picker doesn't copy it), and removing the brand image deleted that file, so the card's picture returned 404. The delete route now checks first and keeps the file while any card in the workspace still shows it: a card's `output.image` or a post pack's `output.card.image` (a new `image_key_in_use` in `generations_service`). The image still leaves the library either way, and its file is still deleted when nothing uses it. If such a card later changes or loses its picture, the kept file stays in storage, the same as any other uploaded card picture. The Settings confirm dialog now says cards that already use the image keep their picture, and the route's docstring matches. The lookup only reads card and post pack rows, through the existing `(workspace_id, type)` index. Gate: pytest 321 (+6: a card and a post pack each keep the file; a card that cleared or swapped its picture, a text post, and a card in another workspace don't), vitest 180. Verified live against the dev database and storage: a brand image a card uses leaves the library and its file still serves (200); one nothing uses has its file deleted (404).

### Fixed: a deleted generation's files are removed; no font requests that can only 404

Deleting a generation removed its record but left its built `.docx`, `.pdf`, or `.pptx` in storage for good. The delete route now also removes that generation's `documents/<id>/` folder (a new `build_document_prefix` keeps the path in one place with `build_document_key`), only after the record was deleted, so the id is a real generation in that workspace (normalized, since `ObjectId` accepts uppercase hex but the files were saved under the lowercase id). ### Security: secrets never print, and the API docs are off in production

`Settings`' default repr included the API keys, so any traceback or log line that showed it printed them (it happened during the CSP work). The secrets (`jwt_secret_key`, `anthropic_api_key`, `openai_api_key`, `unsplash_access_key`, and `mongodb_url`, which can carry database credentials) are now `SecretStr`, read with `.get_secret_value()` only where each is handed to its provider, so printing the settings shows `**********`. This also avoids a trap: `SecretStr("")` is truthy, so the two "is a key set?" checks read the value explicitly. While checking a misconfigured production boot, a second leak turned up: pydantic's validation error quotes the raw input as `input_value`, truncated but still ending in the tail of a key, straight into the container logs. `hide_input_in_errors=True` stops that, and the boot still fails closed with the same clear JWT message. `environment` is now a fixed set (`development` or `production`), so a typo such as `prod` fails at boot instead of quietly skipping the production checks. In production FastAPI's `/docs`, `/redoc`, and `/openapi.json` are now off (they'd give anyone probing the public demo a map of every route), so those paths serve the SPA under its CSP, and the CSP's docs exemption is now read from the app itself, so it exists only where the docs do. The fail-closed JWT secret check (SEC-06) had no tests; it does now. DECISIONS #37. Gate: pytest 310 (+16 in `test_settings_secrets.py`: nothing prints a secret or Mongo credentials, validation errors (field-level and the model-level check) echo no input or key fragment, the providers get the raw keys, a JWT round trip, the SEC-06 checks, an unknown environment rejected, the docs exemption gone without docs, and the real app booted in production serving no docs or schema, mutation-checked); verified live on the dev server (sign-in, Unsplash search, and a generation with the real keys) and on the production image (`/docs`, `/redoc`, `/openapi.json` serve the SPA with its CSP; a boot with a short JWT secret exits 1 with no key in its logs).

### Security: an enforcing Content-Security-Policy (known-gaps step 2)

The app sent no CSP (AUDIT SEC-11 note, QA row H3). `SecurityHeadersMiddleware` now sends one on every response, alongside the existing headers. Scripts may only come from the app's own bundle, plus `'wasm-unsafe-eval'` so the card export's WebAssembly (resvg, satori) can compile; inline script and eval are blocked. Styles allow `'unsafe-inline'` for the `<style>` element Radix dialogs inject. The only outside origins are jsDelivr (card fonts) and Unsplash's two image CDNs. `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, and `frame-ancestors 'none'` close the rest. It goes on every response, so a user-uploaded file opened directly can't run script either; FastAPI's own `/docs` and `/redoc` pages are exempt (they load Swagger UI and ReDoc from jsDelivr with an inline script). A new `csp_mode` setting (`enforce` by default, `report-only`, `off`; documented in `server/.env.example`) can ease it off after a deploy without a code change. The Vite dev server sends no CSP, so the policy was checked on the production image with live models: a Playwright pass collected every `securitypolicyviolation` event while walking demo sign-in, all four Generate modes, card PNG export (with an Unsplash photo, a brand image, and an uploaded font), the image picker, document and template downloads, History, Settings (themes, font previews, "Learn from an image"), and dark mode. It found no violations from the app (the one block was a placeholder image URL stored on an old demo generation), and a probe confirmed an injected inline script and an image from an unlisted host are blocked. DECISIONS #36. The CI `docker` job now also requires the header on the SPA. Gate: pytest 296 (+8 in `test_security_headers.py`: the directives, the other headers unchanged, report-only and off modes, an SSE stream still streaming with the header, an unknown mode rejected, the real app sending it, and the docs pages exempt).

### Security: one AI-call counter for the demo quota (known-gaps step 1)

The demo account's daily cap (50) counted the generations it had saved that day, so the three paid routes that save nothing (brand extract, template "Draft with AI", fill from a document) were bounded only by the per-IP rate limit, and many visitors together could spend on them without limit. Every paid model route now depends on `enforce_demo_ai_quota`, which consumes one unit of a per-account, per-UTC-day counter in a new `usage` collection (`server/app/services/usage_service.py`; TTL index on `expires_at`). Admission is one conditional upsert, so concurrent requests can't overshoot; when it hits a duplicate key, a plain conditional update decides, so a first-of-the-day race isn't refused. A unit is charged on admission (before body validation) and isn't refunded if the request then fails or returns without a model call; that can over-count but never under-count. The 429 now reads "The demo's daily limit of AI actions has been reached. Try again tomorrow." Non-demo accounts are never counted, and the setting keeps its name (`demo_daily_generation_limit`). `ensure_indexes` drops the `generations (owner_id, created_at)` index that only backed the old count. DECISIONS #35; `DATA_MODEL.md` documents `usage`. Gate: pytest 288 (+30 in `test_demo_ai_quota.py`: the limit, 15 concurrent admissions against a limit of 10, a first-of-the-day race, a UTC day rollover, a zero limit, the TTL index and the old index's removal, and each of the seven paid routes answering 429 for the demo, never for a non-demo user, and charging exactly one unit; the route check was mutation-tested); verified live with the limit at 3 (brand extract, AI fill, and a text post each used one unit, then the API and both the Templates and Generate screens showed the limit message).

### Fixed: the production image served a blank page

Found while planning the CSP ([`docs/known-gaps-plan.md`](./docs/known-gaps-plan.md), step 0). With `ENVIRONMENT=production` (the Docker image), the server mounted `dist` at an unused `/static` and answered every other path with `index.html`. Vite's `index.html` loads its bundle from `/assets/*.js|css`, so those came back as `text/html`, the browser refused them under strict MIME checking, and `#root` stayed empty. The CI `docker` job only checked that `/` contained `id="root"`, and the QA pass ran on the Vite dev server, so neither saw it; nothing had been deployed. A new `server/app/spa.py` (`mount_spa`, called last in `main.py`) mounts one `StaticFiles` subclass at `/`. Real files are served as files, and hashed Vite output is cached as immutable. Any other path is a client route and gets `index.html` with `no-cache`, including `/assets/` (also the Assets page). A missing hashed bundle file is a real 404, and an unknown `/api/...` path (any method, any case) is a JSON 404. Dotfiles are never served, font MIME types are registered for the slim image, and HEAD, threadpool lookups, and the traversal guard come from Starlette. The CI `docker` job now also fetches the bundle `index.html` references and requires a JavaScript content type, plus a 404 for an unknown API path. Gate: pytest 260 (+15, `test_spa.py`), ruff, mypy; the image was built and booted locally, every page rendered for the demo account in Playwright, and the CI checks passed against it.

### Fixed: "Remove image" now saves (QA-07)

Removing a card's image only cleared it on screen; the saved generation kept it, so it came back on reload or from History. The generation PATCH now accepts an explicit `image: null` (other nulls are still ignored), and the client sends it, clearing the card once the server confirms; on failure the image stays with an error. ### Fixed: a reload during sign-in left a half-signed-in session (QA-02)

Sign-in stored the token (and `isAuthenticated: true`) before `/auth/me` returned, so a reload in that window persisted a session with no user, and a demo visitor saw owner controls the server then refused. Token and user are now stored together, only after `/auth/me` returns (the new token is sent explicitly). A stored session without a token or a well-formed user counts as signed out on load, which also repairs browsers already stuck in that state. The request interceptor no longer overwrites an explicit `Authorization` header, only one sign-in can run at a time, and a failed `/auth/me` now shows its error on the login page. Gate: vitest 124 (+5); verified live with `/auth/me` delayed. PR #62.

### Changed: Node 24 LTS everywhere, from one `.nvmrc`

CI, the Docker image's client build stage, and local dev all pinned Node 20, which reached end of life in April 2026 (GitHub had also started forcing Node 20 actions onto Node 24). Node 24 has been the active LTS since October 2025. A committed `.nvmrc` (`24`) is now the single source: both `setup-node` steps read it via `node-version-file`, and a CI step fails if any `FROM node:` stage in the Dockerfile drifts from it (the Dockerfile can't read `.nvmrc`; it holds a bare major, a leading `v` tolerated). ### Added — Phase 6: Robustness — `0.8.0` *(PR-B: ingestion safety + concurrency + demo-guard)*

- **Bounded ingestion** — the parse runs off the event loop (`asyncio.to_thread`) under a 30 s timeout (`PARSE_TIMEOUT_S`), and the chunk count is capped (`MAX_CHUNKS = 400`): an over-cap document is marked `error` with **nothing upserted** (rejected, not silently truncated). - **Client — third Generate mode (Text / Card / Document)** — reuses the brief box + retrieval debug panel. `DocumentArtifact` renders an archetype in its own shape: the one-pager as branded **"paper"** (`DocumentPage`), the short-deck as a stack of branded 16:9 **slide cards** (`DeckPreview`) — both in workspace colors/fonts, mirroring the generated file (never Folio chrome, DESIGN §7). A **multi-format download row** pulls each pre-rendered file through the auth-gated route as a blob with **no model call**. History gains a Documents filter, a compact thumbnail, and the same download row on grid cards + the detail dialog.
- **Tests** — pytest (+8, 39 total): python-docx **style assertions** (title = brand heading font + primary brand color, no app fonts) on a built `.docx`; the `.pptx` is a branded deck (slide count, brand font + color); PDF is valid; `build_document_output` clamps a runaway model; `/generate/document` persists `type:"document"` + builds both formats; empty corpus blocks Claude; the download route is ownership-scoped and rejects unknown formats/ids.
