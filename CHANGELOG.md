### Changed — Audit ARCH-05: consolidate DoS/upload caps into `app/limits.py`

Finishes the ARCH-05 structural cleanup ([`docs/AUDIT-2026-07.md`](./docs/AUDIT-2026-07.md) `ARCH-05`): the app's DoS/upload ceilings were scattered across six modules, so "what are our limits?" meant reading six files. A new pure-constant `app/limits.py` (imports nothing from `app`, so no cycle) now owns all seventeen: the five per-file-class upload byte caps (`MAX_IMAGE/ASSET/TEMPLATE/SOURCE/FONT_BYTES`), the four `brand_profile` collection count caps (`MAX_EXEMPLARS`/`MAX_BRAND_IMAGES`/`MAX_UPLOADED_FONTS`/`MAX_CARD_PRESETS`), the zip-bomb bounds (`MAX_UNCOMPRESSED_BYTES`/`MAX_COMPRESSION_RATIO`), and the untrusted-upload processing caps (`MAX_PDF_PAGES`, `MAX_CHUNKS`, `MAX_SOURCE_CHARS`, and the two parse-time budgets). Enforcement stays in each consuming module — only the numbers moved, imported via `from app.limits import …` (name-binding, so every `module.CAP` reference and monkeypatch still resolves). Killed a genuine duplication (`MAX_PDF_PAGES` was defined as `80` in both `loaders` and `content_extraction`). Deliberately **left** the domain/token caps with their logic per the audit's fuzzy boundary: the Claude `*_MAX_TOKENS` budgets, `template_service`'s `MAX_PLACEHOLDERS`/`MAX_VALUE_LEN`, the rate-limit/demo-quota knobs (already in `config.Settings`), and outbound HTTP timeouts. Pure relocation — no values changed and **no test changed**; the 213-test suite (incl. the `MAX_CHUNKS`/`PARSE_TIMEOUT_S` monkeypatch tests and every upload-cap `409`/`413`) passes untouched, which is the proof of no behavior change.

### Fixed — Audit ARCH-05: atomic capped/deduped `$push` (TOCTOU)

Closes the one genuine bug in the ARCH-05 finding ([`docs/AUDIT-2026-07.md`](./docs/AUDIT-2026-07.md) `ARCH-05`): the four capped `brand_profile` sub-collections (`exemplars` ≤ 5, `brand_images` ≤ 24, `uploaded_fonts` ≤ 8, `card_presets` ≤ 8) were checked in the **route handlers** while `workspace_service` `$push`ed **unconditionally** — a read-then-write window where two concurrent uploads both see `len == MAX-1` and both write, exceeding the cap (and, for fonts/presets, creating duplicate `family`/`name`). The invariant now lives in the service write: each `add_workspace_*` issues a **conditional** `update_one` whose filter carries a `$expr`/`$size` room-for-one-more guard (`_room_for_one`) — plus a `$ne` uniqueness clause for fonts/presets — so MongoDB's document-level atomicity enforces the cap regardless of caller (the "no other caller can honor it" case the audit flagged). A rejected write surfaces as a new `WorkspaceWriteConflict` domain exception (no HTTP in the service layer); the routes keep their pre-checks as the fast path (friendly `409` + skipping the Claude vision call / byte storage in the common over-cap case) and, on the rare lost race, delete any just-stored bytes and return the same `409`. The two font/preset caps moved next to the other two in `workspace_service` (one place — pre-stages a future `limits.py`). Behavior for the non-concurrent path is unchanged. Tests: pytest (+9, 213 total) — direct-service cap/dedupe guards for all four collections (bypassing the route pre-check), the previously-untested font route cap + `family` dedupe `409`s, and an `asyncio.gather` concurrency proof that cap+5 simultaneous adds land exactly the cap.

### Security — Audit Phase B1: input & response hardening

The no-new-dependency hardening from the audit backlog ([`docs/AUDIT-2026-07.md`](./docs/AUDIT-2026-07.md)). The **font-family CSS injection** is closed on both font paths — `@font-face` is registered through the CSSOM `FontFace` API (the family is passed as data, never interpolated into a `<style>` string), the CDN font-URL slug is sanitized to strip breakout characters, and the uploaded family name is allow-listed at the server boundary (`SEC-11`). ### Added — Phase 6: Robustness — `0.8.0` *(PR-B: ingestion safety + concurrency + demo-guard)*

Make ingestion **bounded + retryable**, make generation streams **safe across workspace switches and stalls**, and close the **demo-guard gap** on card-image upload — completing Phase 6. See [`docs/DECISIONS.md`](./docs/DECISIONS.md) (#26) and the spec/plan under `docs/superpowers/`.

- **Bounded ingestion** — the parse runs off the event loop (`asyncio.to_thread`) under a 30 s timeout (`PARSE_TIMEOUT_S`), and the chunk count is capped (`MAX_CHUNKS = 400`): an over-cap document is marked `error` with **nothing upserted** (rejected, not silently truncated). A timeout or empty/oversized doc surfaces a friendly asset error.
- **Retryable ingestion** — a demo-blocked `POST …/assets/{id}/reingest` (+ an asset-row **Retry** button) drops any prior vectors **first**, then `mark_processing` resets the asset (clears the error and, if it was `ready`, decrements the workspace's ready-chunk count) and re-runs ingestion out of band.
- **Stream safety** — each generation hook aborts its in-flight `AbortController` and resets state when the **workspace changes** (`useEffect([workspaceId])`, all four hooks), so a stream can't write into another workspace's view. The SSE reader gains a **30 s inactivity timeout** (`STREAM_INACTIVITY_MS`; each `read()` races a timer — a stall cancels the reader and surfaces an error) and a **type-guarded `onError`** (a non-string `error` frame falls back to "Generation failed.").
- **Demo-guard reconcile** — `require_not_demo` now also guards the card-image upload (`POST …/images/upload`), matching the UI that already disabled it for demo users.
- **Dashboard error state** — a friendly banner when the active-workspace query fails ("Is the server running?").
- **Tests** — pytest (+6, 107 total): parse-timeout + chunk-cap mark the asset `error` with nothing upserted; reingest resets/404s/demo-blocks; image upload is demo-blocked. Vitest (+3, 49 total): the SSE inactivity timeout + type-guarded `onError`, and abort-on-workspace-switch.

### Added — Phase 6: Robustness — `0.8.0` *(PR-A: pagination + isolation test)*

- **Paginated list endpoints** — `GET …/generations` and `GET …/assets` now take `?limit&offset` (`Query`-bounded to `[1,100]`; defaults 24/30) and return an envelope `{ items, next_offset }`, where `next_offset` is computed with a **`limit + 1` sentinel** (no `count()` on the hot path; `null` when exhausted).
